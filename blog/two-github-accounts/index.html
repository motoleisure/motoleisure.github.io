一台电脑同时使用两个 GitHub 账号

Tim Chan 发布于 2026 年 8 月 31 日

公司号和个人号、主号和小号——很多人都会遇到“一台电脑要伺候两个 GitHub 账号”的问题。 这篇文章记录我用 SSH Host 别名解决它的完整过程：账号选择直接写进仓库的 remote URL， 平时推拉代码零切换，也不会把代码推错号。

问题在哪里

HTTPS + 凭据管理器（或 gh CLI）的方式，同一时间只有一个生效的账号身份。 两个账号并存时，最容易翻车的场景是：本地改了半天代码，git push 却用的是另一个账号的凭据—— 要么被拒绝，要么更糟：提交署名和仓库归属全乱。

解法思路：让每个账号有一把专属 SSH 密钥，再把“用哪把密钥”这个选择编码进 remote URL。 这样账号切换是声明式的，看一眼 remote 就知道归属，不存在运行时状态。

给第二个账号生成专属密钥

不要复用已有密钥。一把密钥对应一个账号，日后吊销、轮换都干净：

ssh-keygen -t ed25519 -f ~/.ssh/id_ed25519_motoleisure -N "" -C "motoleisure404"
  • -f 指定文件名，避免覆盖默认的 id_ed25519；
  • -N "" 表示空口令——本机开发图省事可以留空，在意安全就设一个并交给 ssh-agent 记住。

在 ~/.ssh/config 里起一个别名

在 ~/.ssh/config 追加一段 Host 配置，别名叫 github-motoleisure：

# GitHub second account: motoleisure404
Host github-motoleisure
    HostName github.com
    User git
    IdentityFile ~/.ssh/id_ed25519_motoleisure
    IdentitiesOnly yes

两处细节最关键：IdentityFile 把这把专属密钥钉死在这个别名上； IdentitiesOnly yes 禁止 ssh 顺手尝试其他密钥——少了它，默认密钥可能先被递上去，导致认证到错误的账号。

把公钥登记到 GitHub

复制公钥内容：

cat ~/.ssh/id_ed25519_motoleisure.pub | pbcopy

登录第二个账号，打开 Settings → SSH and GPG keys → New SSH key 粘贴保存。 然后验证。注意验证的是别名，不是 github.com：

$ ssh -T git@github-motoleisure
Hi motoleisure404! You've successfully authenticated...

看到 Hi 用户名! 就说明别名、密钥、账号三者已经对上号。如果这里显示的是主账号的用户名，说明密钥串了，回去检查 IdentitiesOnly。

仓库按别名挂 remote

把 remote URL 里的 github.com 换成别名即可，其余部分不变：

# 克隆新仓库
git clone git@github-motoleisure:motoleisure404/motoleisure404.github.io.git

# 已有仓库改.remote
git remote set-url origin git@github-motoleisure:motoleisure404/motoleisure404.github.io.git

之后所有 fetch / pull / push 走这个别名，自动使用第二账号的密钥； 主账号的仓库照旧用 git@github.com:…，互不干扰。

配套的两件小事

提交署名按仓库区分。SSH 解决的是“推给谁”，git 还需要知道“署名是谁”。 全局配置保持主账号，在第二账号的仓库里局部覆盖：

git config user.name  "Tim Chan"
git config user.email "motoleisure@gmail.com"

gh CLI 多账号。gh 支持 同时登录多个账号： gh auth login 追加第二账号后，用 gh auth switch -u motoleisure404 切换。 这只影响 gh 自己的操作（建仓库、发 PR），不影响 git push 的密钥选择——两条线互不干扰。

总结成一句话：一把密钥、一个别名、remote URL 里写别名。 配置一次性做完，之后没有任何需要“记得切换”的心智负担——这正是这套方案比来回切凭据管理器靠谱的地方。
