训练 64 个 token，外推 1000 倍仍拿 95 分：ICLR 2026 找到了长文本的病根

Tim Chan 发布于 2026 年 9 月 11 日

softmax 必须给每个 token 分一点概率，序列越长越「弥散」；α-entmax 能把无关 token 精确清零。只训 64 长度的模型外推 1000 倍仍拿 95.3%，softmax 跌到 3%。

论文：Long-Context Generalization with Sparse Attention 会议：ICLR 2026（已录用为会议论文） 作者：Pavlo Vasylenko、Hugo Pitorro、André F. T. Martins、Marcos Treviso 机构：Instituto Superior Técnico（里斯本大学）、Instituto de Telecomunicações、TransPerfect、ELLIS Unit Lisbon arXiv：2506.16640v4 · 代码：github.com/deep-spin/asentmax

一个只见过 64 个 token 的小模型，被丢进 6.5 万 token 的序列里做关联检索——准确率还有 95.3%。

这不是数据拟合，是 1024 倍的长度外推。换作今天所有大模型都在用的 softmax 注意力，同样的设置在 1000 倍长度上只剩 3%，基本等于瞎猜。

这篇被 ICLR 2026 录用的论文给出了一个反直觉的诊断：长文本做不好的病根，不在位置编码、不在上下文窗口，而在 softmax 本身。 而解药，是一个能把"无关 token"的注意力精确清零的老朋友——稀疏注意力。

更妙的是，这篇论文的作者之一 André Martins，正是十年前发明 sparsemax 的同一拨人。这等于造病的人，回来亲手把它治了。

一、先看结果：1000 倍外推是怎么发生的

把惊艳的数字先摆出来，后面再讲它为什么成立。

论文做了两层验证：合成任务（精确可控地测试"模型到底学没学到能外推的算法"）和真实语言建模。

合成任务：只训 64，外推到 6.5 万

下图是多 token 关联检索任务（MQMTAR）上的结果。模型训练长度只有 64，然后直接拿去测 2×、4×……一直到 1024×（65536）的序列：

到 1024 倍长度时，差距是断崖式的：

方法 1024×（65K）准确率
Softmax 3.0%
Top-K（硬稀疏） 0.0%
SSMax（可缩放 softmax） 26.7%
α-entmax（固定温度） 9.3%
ASEntmax（本文） 95.3%

💡 关键观察：同样是"稀疏"，Top-K 在长序列上直接归零、α-entmax 固定温度也撑不住——只有 ASEntmax 这种"会自适应"的稀疏，才能在极端长度上保住注意力。

真实语言模型：训 2K 上下文，检索到 16K

合成任务漂亮，真实模型呢？论文训了一个 4.2 亿参数、LLaMA-3 架构的模型，上下文只设 2048，然后在 RULER"大海捞针"任务上外推：

在 16K（8 倍训练长度）的大海捞针上，ASEntmax 拿到 97.4%，softmax 只剩 0.8%。长上下文困惑度上也是同样的故事——softmax 越长越差，ASEntmax 一路下降：

而最关键的一点：这些长文本上的暴涨，没有牺牲短文本能力。 在 Lambada、HellaSwag 等短上下文基准上，ASEntmax 与 softmax 持平甚至更好（Lambada 困惑度还从 52.4 降到 41.6）。

也就是说，这不是用短文本换长文本，是白捡的。

二、诊断：长文本有三种"病"

要理解为什么换一个函数就能治，得先看清 softmax 在长序列上得了什么病。论文把病灶归纳成三个，而且它们是同一个根因的不同症状。

病一：注意力弥散（Dispersion）

softmax 有个铁律：它必须给每个 token 分一点概率，一个都不能是零。

序列一短，这无所谓。但序列越长，非相关的 token 越堆越多，它们每个都"合法地"分走一点点注意力。结果就是：那个你真正该关注的 token，分到的份额被无限稀释。

形式上，softmax 注意力分布的归一化熵会逼近最大值 Θ(log n)——n 是序列长度。长度趋近无穷，注意力分布趋近均匀分布。等于一个手电筒被逼着照亮整间屋子，屋子越大，你要照的那个角落越暗。

病二：表征坍缩（Representational Collapse）

注意力一弥散，连锁反应就来了：经过若干层之后，不同位置的 token 表示会互相趋同，最后谁都认不出谁。Barbero et al. (2024) 已经证明，softmax 注意力下，‖v_n − v*_{n+1}‖₁ 随长度趋于 0——加一个 token，整个序列的表示就被"抹平"一次。

病三：梯度过压缩（Over-squashing）

梯度沿着注意力图反向回流。softmax 是全连接的稠密图，梯度路径数量随深度按 O(n^L) 增长（n 是长度，L 是层数）。路径爆炸式增多，每条分到的信号就指数级变细。长距离的梯度，还没流到位就蒸发完了。

病症 表现 根因
注意力弥散 熵 → log n，逼近均匀 softmax 禁止任何 token 拿 0
表征坍缩 token 表示趋同、不可区分 弥散导致信息被反复平均
梯度过压缩 长距离梯度蒸发 稠密图，路径数 O(n^L)

三条病，一条根：softmax 不允许注意力说"不"。

三、病根：Softmax 太"民主"了

softmax 为什么必须给每个 token 分一点？看它的定义就明白：

softmax(z)_j = exp(z_j) / Σ exp(z_k)

指数函数永远是正的，分母又是所有项之和。所以哪怕某个 token 的分数再低，它分到的注意力也永远大于零。这是数学结构决定的，不是调参能修的。

近年有几条改进路线想绕开它：

  • ALiBi、RoPE 等位置编码——治标，缓解位置偏置，但 softmax 该弥散还是弥散；
  • Scalable-Softmax（SSMax）——按序列长度缩放 logits，治了"弥散"的一半，但注意力依然稠密；
  • Adaptive Temperature——学一个温度控制 softmax 锐度，但温度再怎么调，分布底部那堆小到看不见的概率依然存在。

这些方案都在 softmax 框架内打补丁。论文的态度很直接：与其给病根打补丁，不如换个不生这个病的函数。

四、解药：让注意力有权说"零"

论文换上的，是 α-entmax：

α-entmax(z)i = [ (α−1)·z_i − τ(z) ]+^(1/(α−1))

方括号里的 ·_+ := max(0, ·) 是关键——分数低于阈值 τ(z) 的 token，注意力被精确清零。不是"很小"，是恰好等于零。

这一个性质，治住了三种病的根：

  • 不再被迫给无关 token 分概率 → 弥散消失；
  • 注意力只落在少数相关 token 上 → 表征不再被无关项反复平均 → 坍缩缓解；
  • 注意力图从全连接稠密图变成稀疏图，梯度路径数从 O(n^L) 降到 O(s^L)（s 是非零 token 数，s ≪ n）→ 过压缩减轻。

α 还是一个连续的旋钮，控制稀疏到什么程度：

α 值 对应 性质
α → 1⁺ softmax 稠密，不允许零
α = 1.5 （本文默认） 中等稀疏
α = 2 sparsemax 线性稀疏，最"硬"

📌 一个有意思的轮回：sparsemax（α=2）是 André Martins 本人在 2016 年提出的，α-entmax 是其推广。十年后，同一拨人回来证明：这个当年为机器翻译做的稀疏注意力，恰恰是长文本时代 transformer 的解药。

五、理论保证：为什么稀疏扛得住长度

光说"能清零"不够，论文给了三条理论结果，解释为什么稀疏能扛住任意长度。

性质一：注意力不再被长度稀释

引理 1（非消失性）：往序列里加一个新 token，softmax 一定会严格降低已有 token 的注意力；而 α-entmax 可以做到——已有 token 的注意力一个都不变。

原因正是清零：新加的 token 如果分数够低，它直接被分到 0，根本不参与分母，自然不影响别人。softmax 是"进来一个就分走一点"，α-entmax 是"不够格的，进来也没你的份"。

性质二：熵被钉死，不再随长度爆炸

命题 1：softmax 的归一化熵随长度趋近 1（完全弥散）；α-entmax 只要非零支撑集 s 增长得比 n 慢（|S|=O(n^β)，β<1），熵就被钉在 O(log s) ≤ β < 1。

翻译成人话：只要模型真正在意的 token 数量 s 远小于总长度，注意力熵就不会随长度失控。 序列拉到再长，注意力还是只聚焦在那 s 个 token 上。

性质三：梯度路径从 O(n^L) 降到 O(s^L)

命题 2：每层注意力分布的支撑集不超过 s（s ≪ n）时，梯度有效路径数按 O(s^L) 增长，而非 softmax 的 O(n^L)。

这是个指数级的差距——n=65536、s=8、L=8 时，路径数从天文数字缩到可控量级。论文还做了对照实验：8 层网络的复制任务里，α-entmax 的梯度范数跨深度跨长度都稳得住，softmax 则随长度急剧衰减。在表征坍缩的一探针实验里，softmax 的 L1 差距随长度奔向 0，α-entmax 一直到 12.8 万 token 都保住非零边界。

Softmax α-entmax
注意力熵 → log n（弥散） O(log s)（聚焦）
加 token 对已有注意力 严格降低 可保持不变
表征 随长度坍缩 可保持可区分
梯度路径 O(n^L) O(s^L)，s ≪ n

六、ASEntmax：会"自适应"的稀疏

到这里，一个自然的疑问冒出来：

α-entmax 这么好，为什么直接用固定 α 还不够？上图里固定温度的 Entmax 在 1024× 上也只有 9.3%。

因为固定 α 在极端长度下会"矫枉过正"。

固定稀疏的困境

问题出在 logits 的取值范围会随长度增长。对独立同分布的高斯 logits，期望极差 ∆_n ≈ √(2σ²·log n)——序列越长，最高分和最低分的差距越大。

温度固定时，这个越来越大的 ∆ 会让 α-entmax 越来越"尖"：到极端长度上，注意力全砸到一个 token 上，该关注的多个相关 token 反而被清零了。稀疏过头，变成了瞎。

解法：给每个注意力头一个可学的温度

ASEntmax 给 logits 乘一个随长度、随内容、逐头学习的缩放：

ASEntmax(z) = α-entmax( (δ + β·(log n)^γ) · z )

其中 β、γ、δ 是每个注意力头单独的、可学习的参数，由 query 的投影算出。三个旋钮各有分工：

  • γ 控制"稀疏随长度怎么变"：γ=−0.5 时，恰好抵消 ∆_n 的增长（推导见下），让注意力在长序列上不至于过尖；
  • β 控制缩放强度，每个头学自己的；
  • δ 是基准偏置，论文取 δ=1。

📌 关键的小数学：当 γ=−0.5，β·(log n)^{−0.5}·∆_n = β·(log n)^{−0.5}·√(2σ²·log n) = β·√(2σ²)，与 n 无关。这一步把"随长度爆炸的取值范围"按住，注意力锐度从此不再随长度失控。

为什么必须逐头

论文在 1.2 亿参数、FineWeb 上训了 50 亿 token 的模型上观察各头学到的缩放曲线，结论很清楚：不同头的稀疏模式差异巨大，简单 log 缩放（SSMax 那种）对很多头拟合很差，加上 γ 次方后拟合显著变好。一个全局参数照顾不了所有头。

而且这套缩放只动 logits，底层直接复用 α-entmax 的快速 kernel（AdaSplash），无需改算子——工程上很干净。

七、NAPE：位置编码也得配合

稀疏变换不只是重新分配权重，它改变了注意力图里哪些边存在。这让位置编码的选择变得很微妙。论文对比了三种：

位置编码 配 α-entmax 的效果
NoPE（不加位置） 纯靠内容，语义检索强，但无位置先验、长度迁移弱
ALiBi（线性距离偏置） 产生清晰"截断窗口"，距离够远的 token 直接清零，局部性强
RoPE（旋转） 频率依赖，易出现周期性"死区"，支撑更破碎

论文的取舍叫 NAPE（NoPE + ALiBi）：一半的头用 ALiBi（管局部、给截断），一半用 NoPE（管远程、靠内容检索）。这样既有稳健的局部感受野，又保留了需要时跳到远处取证据的能力。ASEntmax 再配合着随长度调锐度，防止稀疏在极端长度上过激或过散。

论文强调 NAPE 只是"实用默认值"，不算贡献——而且所有注意力方法（含 softmax）配 NAPE 都最好，所以它是个公平的底盘，不是为稀疏量身定做的偏袒。

八、实验全景：合成 + 真实双线验证

合成任务：四种任务一张表

任务 极端外推长度 Softmax ASEntmax
MQMTAR（关联检索） 1024×（65K） 3.0% 95.3%
Reverse（倒序） 8× 0% 56.7%
Copy（复制） 64× 85.5% 86.6%
Sort（排序） 8× 0% 0%

读这张表有几个层次：

  1. 需要全局精确排序的任务更难——Sort 到 8× 时所有方法都归零（ASEntmax 在 4× 还能撑到 79.7%，但再外推也崩），说明长度外推有任务类型的天花板，稀疏注意力不是万能药；
  2. 检索类任务（MQMTAR、Max Retrieval）受益最大——这正对应"在长上下文里精确聚焦固定模式"的场景，也是稀疏注意力的甜区；
  3. ASEntmax 全面优于固定 α-entmax——证明自适应缩放在极端长度上不是锦上添花，是必需品。

真实语言模型：长短两不误

420M、LLaMA-3 架构、DCLM-Edu 数据、训 70 亿 token、上下文 2048：

  • 短文本：Lambada 困惑度 41.6（softmax 52.4）、HellaSwag 33.4（softmax 33.1），其余持平——没掉链子；
  • 长文本困惑度：PubMed 16K 上 12.9（softmax 18.2），ArXiv 16K 上 10.0（softmax 12.7），且仍呈下降趋势；
  • 检索（RULER）：S-NIAH-1 简单版在 8K（4×）仍 99.8%、16K（8×）还有 97.4%；难版（S-NIAH-2）在 2×、4× 外推上也是最佳。

九、这对行业意味着什么

1. 长上下文的瓶颈，可能不在"给更长窗口"，而在"换注意力"

业界这两年的主流打法是把上下文窗口越拉越大——从 32K、128K 到百万 token，配合各种位置编码插值。但这条路的前提是 softmax。论文指出，softmax 在长上下文上的三种病是数学结构决定的，窗口再大，弥散、坍缩、过压缩照样发作。与其无限扩窗，不如换掉那个让窗口失效的函数。

2. 稀疏注意力的"第二春"，且这次是可学的

α-entmax / sparsemax 不是新概念，十年前就为机器翻译提过。但它一直没成为主流——稠密 softmax + FlashAttention 的生态太成熟。这篇论文的贡献是把它接回长上下文时代，并用可学的逐头温度（ASEntmax）解决了"固定稀疏在极端长度上过尖"的老问题，让它在合成任务上做出 1000 倍外推。

3. 训练长度 vs 推理长度的解耦

最实际的意义：你不必为了支持长上下文就训超长序列。训 2K、推理 16K 还能大海捞针拿 97.4%——长上下文能力的获取成本，可能比想象低得多。对算力有限的团队，这是个值得复现的方向。

4. 它和现有的高效推理栈正交

ASEntmax 直接复用 AdaSplash 的 α-entmax kernel，不改算子；论文还指出，那些推理期的动态稀疏方案（注意力 sink、块稀疏预填加速等）和它是正交的，可以叠加以加速推理、同时保留理论好处。不是非此即彼。

⚠️ 理性看待：论文用的是 120M / 420M 的小到中等模型，合成任务上也是浅层小网。这套机制在千亿参数、超长上下文的真实大模型上效果如何、训练稳定性如何、稀疏 kernel 在超大规模上的效率如何，都还需更大规模的验证。Sort 这类需要全局精确排序的任务上，所有方法都外推失败，也说明稀疏注意力并非万能——它最擅长的是"长上下文里精确聚焦固定模式"，而不是"需要全局重排的算法"。

收尾：六个要点

  1. 病根是 softmax：它的数学结构禁止任何 token 拿零，长序列上必然弥散。
  2. 解药是 α-entmax：能精确清零无关 token，从根上治弥散、坍缩、过压缩。
  3. 理论钉死了：熵从 Θ(log n) 降到 O(log s)，梯度路径从 O(n^L) 降到 O(s^L)。
  4. 自适应是必需品：固定 α 在极端长度会过尖，ASEntmax 用可学逐头温度按住 logits 范围的爆炸。
  5. 结果亮眼：合成任务 1000 倍外推仍 95.3%；420M 模型训 2K、检索到 16K 拿 97.4%，且不损短文本。
  6. 造病的人回来治了病：作者 André Martins 即 sparsemax 的提出者，十年后把自家发明接回长上下文时代。

一句话总结这篇论文的逻辑链：

长文本做不好 → 是 softmax 的锅 → 它不允许注意力说"不" → 换成能说"不"的 α-entmax → 再让它学会随长度自适应地"说不" → 1000 倍外推。

最朴素的工程直觉，往往就藏在一个被默认了十年的函数里。
