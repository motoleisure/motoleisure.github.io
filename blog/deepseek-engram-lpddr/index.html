用 LPDDR 取代 HBM：DeepSeek 4.1 Flash 架构里被所有人忽略的关键细节

Tim Chan 发布于 2026 年 9 月 11 日

舆论都在看跑分，硬件分析师 GDP 指出真正的主角：约 196B 参数的 Engram 嵌入驻留主机内存 LPDDR5，把最贵的 HBM 省了下来。这是中国大模型实验室集体转向的新方向。

编译整理｜原作者：GDP（@bookwormengr）· 2026-09-10 · 原文链接 调研与补充：结合 DeepSeek 官方技术报告、Engram 论文（arXiv:2601.07372）及美团 LongCat-2.0、阿里 Qwen3.8-Flash-Next 模型卡

9 月 10 日，DeepSeek 发布 V4.1 Flash。舆论焦点都放在了它的跑分上，但硬件分析师 GDP（@bookwormengr）指出：这代架构里最重要、却几乎被所有人忽略的细节是——它正在用主机内存（LPDDR5）取代昂贵的 HBM。这是中国大模型实验室集体转向的新方向，而背后的关键技术，叫 Engram。

一、被忽略的关键细节：一大块参数住进了"便宜"的内存

DeepSeek 4.1 Flash 最被忽视的架构事实是：逾四分之一（约 196B）的参数——即 Engram 嵌入——并不在 GPU 的 HBM 上，而是驻留在主机内存（LPDDR5）里。这一设计直接省下两样最贵的东西：

  • HBM 用量——HBM 极其昂贵且供应紧张；
  • FLOPs 用量——预填（prefill）阶段原本需要密集算力。

模型的骨干参数（attention、MoE 专家）仍然在 HBM 上，但大多以 4-bit（FP4） 低精度存放；而 Engram 嵌入这块被"搬"到了主机内存里。

📌 作者观点：他在 2026 年 5 月就预测过，"Engram 是中国实验室新的扩展方向"，今天 DeepSeek 4.1 Flash 印证了这一点。近期美团 LongCat 2、阿里 Qwen-3.8-Flash-Next 也都走了同一条路。

二、什么是 Engram？——一句话能说清

用最简单的话讲：嵌入（embedding）存储的是"token 的含义"。

但很多概念需要多个 token 才能表达——"亚历山大大帝"不是咖啡师亚历山大。传统 Transformer 的低层，都在努力从零碎的 token 序列里重新"拼出"这些含义。这是一种浪费的计算：一旦你在序列里遇到"亚历山大大帝"，你本就应该知道这一组 token 代表什么。

Engram 的思路是：把序列的含义（2 个一组的 token、3 个一组的 token）预先存成嵌入，在运行时直接检索回来。一旦你为这些涉及 2-3 个 token 的复杂概念建好了"记忆条目（engram）"，就能省下大量计算和骨干参数，并把这些含义/嵌入放到主机内存（LPDDR）里。

结论：用更低的参数量，获得更高（或相当）的智能。

三、来自原始论文的精确机制

Engram 来自 DeepSeek 团队 2026 年 1 月发表的论文《Conditional Memory via Scalable Lookup: A New Axis of Sparsity for Large Language Models》（arXiv:2601.07372，第一作者 Cheng Xin 等，DeepSeek 团队）。它的核心论断是：

语言建模本质上包含两类性质截然不同的子任务：

① 组合推理（compositional reasoning）——需要深层、动态的计算； ② 知识检索（knowledge retrieval）——大量文本（命名实体、固定搭配、模板化句式）是局部的、静态的、高度刻板的。

标准 Transformer 缺少原生的"知识查表"原语，被迫用计算去模拟检索——解析一个常见的多 token 实体，要消耗好几层 attention 和 FFN，本质上是"在运行时昂贵地重建一张静态查表"。这把宝贵的序列深度浪费在了琐碎操作上。

论文因此提出一个新的稀疏轴：条件记忆（conditional memory）。如果说 MoE 是"条件计算"（稀疏激活参数来处理动态逻辑），那么 Engram 就是"条件记忆"——用 O(1) 的查表来检索静态嵌入。它的几个关键设计：

1. 分词器压缩（Tokenizer Compression）

标准子词分词器优先"无损重建"，常给语义等价的词分配不同 ID（如 Apple 与 ␣apple）。Engram 加一层词表投影，按 NFKC 规范化、小写化把原始 ID 折叠成规范 ID，对 128k 词表实际有效词表压缩约 23%，提升语义密度。

2. 多头哈希（Multi-Head Hashing）

直接给所有 N-gram 组合空间参数化是不现实的。Engram 为每个 N-gram 阶用 H 个独立哈希头，每个头用一个轻量的乘法-XOR 哈希把压缩后的上下文映射到一张素数大小的嵌入表里，再拼接成最终记忆向量——以极低碰撞率实现 O(1) 检索。

3. 上下文门控 + 多分支融合

在多分支骨干里，Engram 共享一张稀疏嵌入表与 Value 投影矩阵，用若干个不同的 Key 投影实现分支特异性门控；这些线性投影可融合为单次 FP8 稠密矩阵乘，最大化 GPU 算力利用率。

四、核心机制：计算与存储解耦，预取-重叠

这是整件事能在工程上跑通的关键，也是"用 LPDDR 取代 HBM"成立的原因。

关键区别在于寻址的可预测性：MoE 的路由依赖运行时的隐状态（必须先算出 hidden state 才知道激活哪个专家，所以专家参数必须在 HBM 里）；而 Engram 的检索索引只取决于输入 token 序列——在 forward 之前就完全已知。这种确定性，让"存储"和"算力"可以被彻底解耦：

  • 训练：把大嵌入表按行切分（shard）到多张 GPU 上，用 All-to-All 通信在前向取出活跃行、反向分发梯度，记忆容量随加速器数量线性扩展；
  • 推理：既然索引提前已知，系统就能经 PCIe 从主机内存异步预取嵌入；把 Engram 放在骨干的特定层，让前面几层的计算"打底"，把取回延迟完全藏起来（overlap），GPU 不必空转。

论文还给出一个硬件-算法协同的权衡：把 Engram 放得越深，能藏延迟的"计算窗口"越大；但消融实验显示，建模性能更偏好早期介入以卸载局部模式的重建。最优位置要同时满足"建模"和"系统延迟"两个约束。

此外，自然语言 N-gram 天然服从齐普夫分布——少量模式占绝大多数访问。Engram 据此设计多级缓存层次：高频嵌入缓存到 HBM 或主机 DRAM，长尾的罕见模式放 NVMe SSD。这让记忆容量可扩展到极大，而对有效延迟的影响极小。

五、U 型缩放律：MoE 和 Engram 的最优配比

论文把"在固定总参数预算下，MoE 专家和 Engram 嵌入槽该怎么分"形式化为稀疏分配（Sparsity Allocation）问题，并发现一条 U 型缩放律：

  • MoE 主导（Engram 占比低）：模型缺静态记忆，被迫用深度和算力重建模式，效率低；
  • Engram 主导（Engram 占比高）：损失条件计算能力，伤害需要动态推理的任务——记忆无法替代计算；
  • 中间最优：把一部分稀疏预算重分配给 Engram，性能最好。该最优点的位置在不同规模下都稳定。

更妙的是"无限记忆"实验：固定 MoE 骨干，只扩大 Engram 槽数（最多加数十亿参数），验证损失随记忆规模呈严格的幂律（对数空间线性）下降——也就是说 Engram 提供了一个可预测的扩展旋钮：加更多记忆持续受益，却几乎不增加计算。

六、DeepSeek V4.1 Flash 的真实架构数据

结合 DeepSeek 官方技术报告，V4.1 Flash 的关键数字如下：

项目 数据
骨干参数（attention + MoE） 552B，驻留 HBM，多为 4-bit
Engram 参数（条件记忆） 196B，均匀分到两个 N-gram 模块，驻留主机内存（LPDDR）
每 token 激活参数 预填 8B / 解码 16B
上下文长度 最高 1M token
架构 CED（因果 Encoder-Decoder）+ CSA2 稀疏注意力 + FP4 KV 缓存
HBM 全局 KV 占用 每 token 仅约 890 字节（始终在 HBM）
训练规模 45T token；稀疏注意力从 64K 序列从头训，无稠密预热
对比 V4-Pro-Base held-out 评测提升 5%–10%，总参数仅为其 1/3、激活参数仅 1/4
代表跑分 GPQA Diamond 90.9；Terminal-Bench 2.1 90.6

💡 DeepSeek 官方公告称：经充分测试，V4.1 Flash 在性能、成本、速度和总耗时上全面超越 V4 Pro，将于北京时间 9 月 14 日 12:00 起把 V4 Pro 的请求路由到 V4.1 Flash 并按 Flash 价计费——V4 Pro 有序退场。

可以看到，DeepSeek 把论文里的 Engram（报告中引为 Cheng et al., 2026b）、预取-重叠、分片嵌入表、推理 kernel 融合一并落地到了产品级系统里。

七、这不是孤例：美团、阿里都在跟进

作者判断"Engram 是中国实验室集体方向"，并非孤证。模型卡证实，另外两家头部实验室同代模型都采用了同源思路：

美团 LongCat-2.0

1.6T 总参数、每 token 激活约 48B 的大规模 MoE，全程跑在"AI ASIC 超算集群"上，预训练 35T token、支持 1M 上下文。它在 Key Features 里明确列出 "N-gram Embedding"，含 135B 的 N-gram 嵌入参数（继承自 LongCat-Flash-Lite），并给出与论文同构的扩展原则：

"MoE 的稀疏度已经越过甜点；N-gram 嵌入的比例被约束在最优区间内"——这两条原则保证 N-gram 嵌起相对同等规模的纯 MoE 的稳健优势。

阿里 Qwen3.8-Flash-Next

官方称为"支撑未来 Qwen4 的架构"的实验预览，亮点包含 QSA（Qwen 稀疏注意力）、Gated Residual，以及关键的 N-gram Embedding。模型卡原话：

"N-gram Embedding 提供了一条独特的参数扩展轴，所需计算更少、且比 MoE 更易于卸载（offload）……对内存受限的加速器，这种方式在不牺牲质量的前提下让参数扩展极为高效。"

"易于卸载"+"内存受限的加速器"——这两句话，几乎就是在直白解释为什么要用 LPDDR 取代 HBM。NVIDIA 还发布了它的 NVFP4 量化版本，呼应"骨干低精度"的整体趋势。

八、为什么是中国实验室？——HBM 短缺下的必然

作者早在 2026 年 5 月就指出：DeepSeek 会大举押注 Engram，因为 DeepSeek/华为系受限于 HBM 供应，而国内其他实验室习惯跟随 DeepSeek 的路线。如今三家同代旗舰不约而同采用"N-gram 嵌入/Engram + 主机内存卸载"，说明这已是行业共识。

背后的逻辑链条很清晰：

  1. 受出口管制与产能限制，国产算力 HBM 紧缺；
  2. Engram 的确定性寻址让大量参数可安全地放到便宜的主机内存（LPDDR/DRAM）甚至 SSD；
  3. 用"查表"替代"重建"，省算力、省 HBM、还能更强；
  4. 长尾齐普夫分布 + 多级缓存，让大容量记忆对延迟几乎无感。

于是"用 LPDDR 取代 HBM"不再是个别实验室的权宜之计，而是一条结构性、可规模化、且已被三家头部模型验证的技术路线。

九、对行业的启示

  • 稀疏有了第二个轴：过去是 MoE"条件计算"一轴，现在多了"条件记忆"一轴，二者呈 U 型最优配比；
  • 记忆是可扩展旋钮：加记忆持续受益、几乎不增算力，且服从幂律；
  • 存储与算力解耦：可预测寻址 = 可预取 = 可卸载到主机内存，HBM 不再是硬瓶颈；
  • 低精度骨干 + 大容量记忆成为新范式：骨干 4-bit/FP4 在 HBM，Engram 在 LPDDR/SSD；
  • 国产算力的出路：在 HBM 受限前提下，用架构创新换等价或更强智能——DeepSeek、美团、阿里已给出示范。
