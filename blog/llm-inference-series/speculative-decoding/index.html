08 · 投机解码（Speculative Decoding）：用小模型加速大模型

Tim Chan 发布于 2026 年 9 月 14 日

投机解码是近年推理加速最聪明的技巧之一：让小模型先"猜"几个 token，大模型一次性验证，猜对的直接接受。它在 decode 阶段（memory-bound）效果尤其好，因为大模型一次验证多个 token 把多次 decode 的带宽开销摊薄成一次。这一篇讲它的原理、几种变体、什么时候有用、怎么调。

投机解码是近年推理加速最聪明的技巧之一：让小模型先"猜"几个 token，大模型一次性验证，猜对的直接接受。它在 decode 阶段（memory-bound）效果尤其好，因为大模型一次验证多个 token 把多次 decode 的带宽开销摊薄成一次。这一篇讲它的原理、几种变体、什么时候有用、怎么调。

一、动机：decode 的尴尬

回顾：decode 阶段每生成一个 token，大模型要把整个权重读一遍 HBM，算一个 token 出来。GPU 大部分时间在等数据。一个 token 一次 decode，一次 decode 读一遍权重——这浪费。

如果能让大模型一次前向处理多个 token 的计算，不就把多次 decode 的带宽开销摊薄了吗？但大模型是 autoregressive 的，怎么一次算多个？

投机解码的答案：让小模型先猜几个 token（draft），大模型一次性验证这整段（用一次前向算多个位置的 logits），猜对的全接受，猜错的从第一个错的地方重算。

二、基本流程（自投机 / draft-target）

1. draft model（小，快，比如 1B）生成 k 个候选 token: [t1, t2, ..., tk]
   （它一次 decode k 个 token，快，因为小模型权重小、带宽省）

2. target model（大，慢，比如 70B）一次性对 [prompt + t1..tk] 做一次前向
   得到每个位置的 logits: [l_0, l_1, ..., l_k]
   注意：这一步 target model 一次前向算了 k+1 个位置的 logits！
         而不是 k 次单 token decode。带宽开销被摊薄。

3. 验证（rejection sampling）：
   for i in 1..k:
     比较 target 在位置 i 的分布 和 draft 的 ti
     如果 ti 在 target 分布里"合理"（按概率接受/拒绝）
       接受 ti，继续
     否则：
       从 target 分布重新采样一个 token 替换 ti
       从这里打断，后面 draft 的 token 全废
   
4. 接受的 token 全加入输出；从打断点重新让 draft 猜下一段

关键点：大模型一次前向验证 k 个 token，把 k 次 decode 的带宽开销压成一次。 即使 draft 猜错一部分，只要接受率（acceptance rate）够高，总 token 数 ÷ 大模型前向次数 还是 >1，就是净赚。

三、理论保证：输出分布不变

投机解码用 rejection sampling 验证，数学上保证最终输出的分布和大模型单独采样完全一致。也就是说，投机解码不改变输出质量（理论上），只是加速。这是它和"直接用小模型输出"的本质区别——小模型只用来猜，最终接受的是大模型的分布。

实践注意：理论保证假设确定性采样。实际有浮点误差、draft/target tokenizer 不一致等问题，输出可能略有差异。做关键场景要对照验证。

四、变体：谁当 draft model

4.1 小模型当 draft（经典）

用一个参数量小很多的小模型（如 Llama-68M 给 Llama-7B 当 draft，或 1B 给 70B）。draft 快、但猜得可能不准（和 target 分布差大 → 接受率低）。

4.2 N-gram / 简单模型当 draft

更激进：用 n-gram 模型（几乎零开销）当 draft，猜重复模式（代码、结构化文本接受率高）。适合高度重复/模式化输出。

4.3 EAGLE / Medusa：draft model 是 target 的轻量预测头

更聪明的方向：不在大模型外挂小模型，而是在大模型的 hidden state 上训一个轻量预测头，预测接下来几个 token 的 hidden state 或 logits。

  • Medusa：在 target 模型每个位置加几个"额外头"，每个头预测未来第 2、3、4... 个 token。一次前向就能拿到多个候选。不需要独立 draft model 的前向开销。
  • EAGLE：用一个小的 transformer 头，输入 target 的 hidden state，预测下一层的 hidden state（而非直接预测 token）。更准，接受率高。

这些"自投机"方案不需要独立小模型，部署简单，接受率高，是当前主流。

4.4 新一代：DFlash / Spec V2

SGLang 社区在推新一代投机解码（DFlash、Spec V2），针对更大模型和更高接受率优化。这是 2025-2026 的前沿，关注 SGLang/LMSYS 的 blog 跟进。

五、什么时候投机解码有用（和没用）

5.1 有用的场景

  • decode 是主要瓶颈（输出生成长）。
  • draft 和 target 分布接近（同家族模型，如 Llama 小→Llama 大）。
  • 输出有模式/重复（代码、结构化文本），接受率高。
  • batch 小（单请求或低并发，batch 大时单次 decode 已经摊薄带宽，投机收益降）。

5.2 没用甚至更慢的场景

  • draft 猜得差（接受率 <30%），验证开销 > 节省。
  • prefill 主导（短输出长 prompt），投机只加速 decode。
  • batch 大：大 batch 时每次 decode 已经算很多 token，带宽已摊薄，投机的相对收益小，draft 的额外开销可能反噬。
  • draft model 太大：draft 本身 decode 也慢，净收益消失。

实践经验：投机解码在单请求/低并发、长输出生成、同家族大小模型配对时收益最大。高并发大 batch 场景，continuous batching 已经把带宽摊得很好，投机收益有限，要测。

六、怎么衡量投机解码的效果

不是"开了就快"，要量化：

  • 接受率（acceptance rate）：draft 猜的 token 被大模型接受的比例。>50% 算好用，>70% 很好。
  • 加速比：(输出 token 数) / (大模型前向次数)。>1 才是净赚。理想接近 1+平均接受长度。
  • 端到端延迟/吞吐：最终看 E2E，不是单看接受率。

注意：投机解码增加大模型单次前向的计算量（一次算 k 个位置），所以单次前向变慢，但总前向次数变少。净收益 = 次数减少 ÷ 单次变慢。

七、实战启动

7.1 vLLM 投机解码

# 用 n-gram 当 draft（最简单，零额外模型）
vllm serve model \
  --speculative-model "[ngram]" \
  --num-speculative-tokens 5 \
  --ngram-prompt-lookup-max 4

# 用小模型当 draft
vllm serve meta-llama/Llama-3.1-70B \
  --speculative-model meta-llama/Llama-3.2-1B \
  --num-speculative-tokens 5

7.2 SGLang 投机解码

python -m sglang.launch_server \
  --model-path meta-llama/Llama-3.1-70B \
  --speculative-algo EAGLE \
  --speculative-draft-path ... \
  --num-speculative-tokens 5

7.3 调参要点

  • --num-speculative-tokens：draft 一次猜几个。太多 → 猜错率高浪费；太少 → 摊薄不够。5-8 常见，要测。
  • draft 模型选择：同家族、同 tokenizer、参数量 1/10 到 1/50。
  • 开启后重新测质量：输出分布理论不变，但实测要对照关键指标。

八、投机解码和其他优化的关系

优化 主要省什么 和投机解码关系
量化 权重带宽（decode） 正交，可叠加（小 draft + 大 target 都量化）
Prefix caching prefill（TTFT） 正交，投机主要管 decode
Continuous batching 带宽摊薄 部分竞争：大 batch 时 batching 已摊薄带宽，投机收益降
Chunked prefill prefill 平滑 正交

实践：投机解码不是"万能加速器"，它是低并发 + 长 decode 场景的针对性武器。开之前先确认你的瓶颈是 decode 且并发不高，再测接受率和净加速。

九、一个常被忽略的点：输出一致性

投机解码理论上不改变输出分布，但工程上：

  • draft 和 target tokenizer 必须一致，否则 token 边界对不上，验证逻辑出错。
  • 采样要确定性（固定 seed / temperature 一致），否则验证的接受/拒绝逻辑乱了。
  • 浮点非确定性：不同 batch size、不同卡上 target 的 logits 可能有微小差异，导致接受边界 token 不稳定。

Inference Lab 的 vLLM 编译对比文章提到一个相关现象：eager 和 compiled 两条路，12 个请求里 4 个输出不同。这还只是编译差异。投机解码引入 draft 后，输出差异更可能。做生产前要测：开投机 vs 不开投机，输出质量是否一致。

十、Lookahead 与模型无关投机（Atlas #16 补强）

前面几节讲的投机解码都要 draft model（小模型或 EAGLE/Medusa 头）。但还有一类不需要配对同家族小模型的投机——靠 prompt 本身或 target 自己做并行猜测，部署门槛更低。这一节补 Atlas #16：n-gram prompt-lookup、lookahead decoding、retrieval-based 投机。

10.1 N-gram / Prompt Lookup（已在 4.2/7.1 提过，这里深化）

思路：用 prompt 里已有的 n-gram 当 draft——如果输出和 prompt 有重复片段（代码、结构化文本、引用原文），直接从 prompt 里「查」出后续 token 当候选，大模型验证。

  • 零额外模型：n-gram 查表几乎零开销，draft 阶段几乎免费。
  • 接受率视场景：代码补全、文档摘要（引用原文）、格式化输出 → 接受率高（重复多）；开放对话、创意写作 → 接受率低（少重复）。
  • vLLM 的 --speculative-model "[ngram]" 就是这条路线（7.1 已给命令）。
  • 适用判据：你的输出有多少和 prompt/历史重复？重复多→好用，重复少→接受率低、浪费。

10.2 Lookahead Decoding：Jacobi 自投机

思路：不用 draft model，用 target 模型自己做并行猜测。基于 Jacobi 迭代——把 autoregressive 解码看作一个不动点问题，一次前向并行猜未来几步，再用验证修正。

  • 不需要任何 draft model：省去配对小模型 / 训练 EAGLE 头的部署成本。
  • 不需要同家族配对：纯 target 自己，模型无关性最好。
  • 代价：猜的准确率不如专门训练的 EAGLE 头（EAGLE 学过怎么猜），接受率中等。适合「不想配 draft model、想白嫖一点加速」的场景。

10.3 Retrieval-based / REST 投机

思路：从一个外部语料库（或自己之前的输出缓存）检索出和当前上下文匹配的片段当 draft，大模型验证。类似 RAG，但检索的是「续写候选」而非「知识」。

  • 适合：高度模板化输出（合同、报告、固定格式 JSON）。
  • 代价：要维护语料库 + 检索索引，工程复杂。

10.4 模型无关投机的好处与边界

方案 要 draft model？ 要配对同家族？ 接受率 适用
N-gram prompt lookup 否 否 视重复率 代码/结构化
Lookahead decoding 否 否 中等 不想配 draft 的通用场景
REST retrieval 否 否 视语料 模板化输出
EAGLE/Medusa 要（轻量头） 要训练 高 主流生产
小模型 draft 要（小模型） 要同家族 高 有配对小模型

核心好处：模型无关投机把「部署投机解码」的门槛从「得有配对小模型」降到「装个开关」——适合快速试水。但接受率上限不如专门训练的 EAGLE 头。

10.5 tradeoff

  • 接受率是命门：n-gram 在开放对话里接受率可能 <30%，验证开销 > 节省 → 反噬。先测接受率再决定开不开。
  • 和 continuous batching 竞争（第 06 篇）：大 batch 时投机收益降，n-gram 也不例外。
  • 输出一致性：即使 n-gram，验证还是 target 模型做，理论分布不变——但工程上仍要对照测。

十一、实践 checklist

  • [ ] 确认瓶颈是 decode（非 prefill）且并发不高，再考虑投机
  • [ ] draft 和 target 同家族、同 tokenizer
  • [ ] 测接受率，>50% 才值得开
  • [ ] 测净加速比（E2E），不是单看接受率
  • [ ] 大 batch 场景先测，可能收益有限甚至反噬
  • [ ] 开启后对照输出质量，确认分布一致性
  • [ ] num-speculative-tokens 调参测不同值（5-8 常见起点）
  • [ ] 优先试 EAGLE/Medusa 自投机（无独立 draft 前向开销），其次小模型

十二、原书补强：四条操作规则 + EAGLE 细节（Kiely §5.2）

精读原书 §5.2 后补四条本篇没讲透的操作点。

1. draft 模型的 10× 规则。 draft-target 方案里，draft 模型宜比 target 小至少一个数量级（≥10× 参数），且最好是同一家族（共享 tokenizer、行为相近）。可用蒸馏/微调把小模型调得更像 target 以提高接受率。

2. 拒绝级联。 投机序列里一旦某个 draft token 被拒，其后整段全部丢弃，不接受“跳过错误那个继续往后接”。所以目标不是“长序列”，而是短而高接受率的序列——生成+验证虽比生成便宜，但仍有实质开销，长序列一旦早段被拒就全亏。

3. 高并发要动态关掉投机。 投机只对低–中 batch有用（decode 时 compute 有空闲）。batch 大到 compute 饱和时，验证开销吃不掉、反而拖累，推理引擎要能按负载动态关闭投机。这是“低并发+长 decode 才用投机”原则的操作面。

4. EAGLE 的真实参数。 EAGLE 是从零训练的专用 draft 模型，不是拿现成小模型：输入 3 个 hidden state（早/中/晚各一层）、输出最多 8 个 draft token（2× Medusa）、<1B 参数；关键工程优势是它能挂在和 target 同一个 PyTorch class 上，一次前向同时跑 target + EAGLE，免去 draft-target 那种多次 CPU 来回编排。n-gram 路线相反：可 >10 token（比 EAGLE 长），但只有输出≈输入时接受率高（代码补全/修改）；lookahead 在推理中生成 n-gram 填字典（比 n-gram 通用、但要额外 compute）。
