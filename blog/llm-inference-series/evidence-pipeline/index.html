14 · 证据体系：从 Inference Lab 8 篇提炼的可信推理评估流水线方法论

Tim Chan 发布于 2026 年 9 月 14 日

前面 13 篇讲"做什么"。这一篇讲"怎么相信你做的有效"。它从 Siddhant Khare 的 Inference Lab 8 篇文章里提炼出一套证据优先的推理评估方法论——这是 inference engineer 区别于"会跑 vLLM"的人的真正分水岭。

前面 13 篇讲"做什么"。这一篇讲"怎么相信你做的有效"。它从 Siddhant Khare 的 Inference Lab 8 篇文章里提炼出一套证据优先的推理评估方法论——这是 inference engineer 区别于"会跑 vLLM"的人的真正分水岭。

一、为什么需要证据体系

Inference Lab 的 benchmark-evidence-lineage 文章开头一句话点题：

一个 benchmark 截图可以是真且无用的。 它能显示模型名、延迟、绿色条，但很少告诉你哪个模型 revision 跑了、什么代码观测的、计时从哪开始、响应是否完整、哪些制品留存、哪个价格产生了成本。你能读出数字，但无法检视它的 lineage。

证据体系要解决的就是这个 gap：让每个性能结论可追溯、可复现、有边界。 不是为了论文漂亮，是为了：

  • 发版回归时能判断"真的变快了吗"还是"噪声"。
  • 对比选型时能判断"这两个数字可比吗"。
  • 出问题时能回溯到精确版本/配置/制品。
  • 别人（或三个月后的你）能复现并信任。

二、八个 lineage 维度

Inference Lab 提出，一个性能结果要可信，至少要能回答八个问题：

  1. 模型身份：哪个 repo / revision / quantization / serving name？
  2. 运行时身份：哪个 collector / framework / driver / OS / 配置？
  3. workload 身份：哪个 prompt fixture / token 数 / cap / 重复 / warmup / 停止规则？
  4. 评估器身份：哪些检查决定输出合法/完整/合格？
  5. 测量 scope：TTFT 是 client 观测 / provider 上报 / trace 推导 / log 推断？
  6. 制品身份：哪个 manifest / summary / samples / logs / checksums？
  7. 定价身份：成本来自公开 price sheet / 账户 billing / provider usage？
  8. 失败状态：complete / truncated / timeout / OOM / refused？

实践：每出一个性能数字，旁边要能填全这八项。填不全的数字，当截图对待。

三、证据节点（Evidence Node）

把一个结果做成最小可独立的对象，绑定：身份 + scope + 状态 + 一个或多个已验证制品。一个简化样例：

{
  "evidence_id": "openrouter-glm-2k-comparison-20260902",
  "kind": "hosted_comparison",
  "status": "verified",
  "outcome": "comparison",
  "model": {
    "id": "z-ai/glm-5.3 and z-ai/glm-5.3-flash",
    "revision": "z-ai/glm-5.3-20260816 and z-ai/glm-5.3-flash-20260826"
  },
  "measurements": [
    {"scope": "client timing",
     "provenance": "network, gateway, queueing, and execution combined"}
  ],
  "supported_claims": ["timing", "quality", "cost"],
  "unsupported_claims": ["memory", "model_fit", "deployment_readiness"]
}

关键：每个 claim 显式标 supported / unsupported / not_applicable。 不留模糊的"空白可能是否"。

四、Claim Matrix：把声明做成数据

Inference Lab 的证据目录把 9 个证据条目 × 7 个 claim 维度做成一个矩阵，63 个 cell，每个是三态之一：

状态 含义
supported 在 scope 内，证据支持这个 claim
unsupported 在 scope 内，但证据不支持
not_applicable 这个 claim 不属于该证据
（missing） 目录里没声明 = 图完整性错误，不是"否"

举例（Metal PID 归因证据）：

目标 PID interval 数匹配已知 dispatch 数？  → supported
证据报告 GPU 利用率？                        → unsupported
托管 token 定价适用本地 capture？            → not_applicable

实践：把每个性能证据的"它支持什么/不支持什么"做成表格。这逼你在出结论前就想清楚边界。"这不证明什么"比"它证明了什么"更重要写出来。

五、null ≠ zero

这是贯穿 Inference Lab 的铁律。一个 OOM 前没首 token 的记录：

first_token_ms: null        ← 不是 0（0 = 边界时刻有事件）
completion_tokens: null     ← 不是 0（0 可能是合法空响应）
estimated_cost_usd: null    ← 不是 0（0 可能是免费层）

每个 zero 都是一个 claim。 把缺失当 zero 会编造数据。缺证据就留 null。系统要在 null 时拒绝计算（如 cost 为 null 不报性价比，不报"无限价值"）。

六、独立 Oracle 校验

Inference Lab 的方法论核心：永远不只信系统自己的报告。 几个实证：

6.1 KV cache 命中（KV-cache truth auditor）

引擎报"cache hit 8 token"。独立 token oracle 按精确 token 身份 + cache 策略重算"预期复用 8"，再核对 prompt path 实际处理 1 token。三路一致才算 verified_hit。

10 个合成 case 全过——证明审计路径、oracle、attestation、evaluator、schema、隐私规则、hash、独立 verifier 都对。

6.2 Metal dispatch 数

解析器报"400 个目标 PID interval"。用已知 dispatch 数（400）当 oracle 核对。匹配 = 解析器可信。"合理数字"不是 proof，已知 oracle 才是。

6.3 编译 break-even

vLLM compiled 的 12 请求 latency 比和低，能声明"break-even 在 113 请求"吗？Inference Lab 的判断：113 是建模（冻结观测序列外推），不是观测。outputs 还不同、correctness 还不同、无 counterbalance 复现。所以不能声明 break-even。

一个模型可以指导下次运行，不必晋升为上次的结果。 这是独立 oracle 思维的精髓——区分"我算出来的"和"我观测到的"。

七、可比性是契约不是视觉

Inference Lab 的 GLM 文章最深的洞见之一（第 5、10 篇也讲过）：

本地 Qwen3-8B MLX 跑 23 cases/min，托管 GLM-5.3 跑 18。能放进一张排行榜说"Qwen 最快"吗？不能。契约不同：

  • 不同模型身份
  • 不同运行时（MLX 本地 timing vs 托管 client timing）
  • 不同推理模式（本地 thinking 关 vs 托管强制 reasoning）
  • 不同 seed / 系统身份 / clean-boot 断言

一个图表能对齐任何三个数字，但不等于它们的分母相等。可比性来自契约，不来自数字的视觉邻近。

横评要么对齐契约，要么显式标"不同契约的观察，不可直接排名"。把排除项写出来——被排除的系统恰恰是"比较诚实"的信号。

八、fail closed：证据系统要像 parser 一样防错

Inference Lab 把证据系统当另一个 parser，要同样的警惕。验证时必须拒绝：

  • 重复 ID：evidence_id 跨 catalog/registry/graph/matrix 必须唯一。静默 last-write-wins 会偷换。
  • 悬空边：每条 edge 端点必须存在。
  • 环：lineage 是 DAG，环让推导顺序歧义。拓扑排序要消费所有节点，否则报环。
  • 路径逃逸：制品路径相对 allowed root，拒绝绝对路径 / .. / symlink 逃逸 / 设备路径。
  • 超大输入：每个 source 有最大 size/artifact 数/node 数/edge 数，超了先拒。
  • commit 不匹配：catalog/registry/graph/matrix/schema/checksum 必须来自同一棵 tree。分支 URL 不够，PR URL 是 context，merged commit 才绑字节。
  • missing claim cell：每个 claim row 必须提供全部七个维度。缺了是错误不是空。

任何一项 fail → 不出报告，而不是出一个"看起来合理"的报告。

九、隐私是发表的一部分

证据要公开可检视，但公开的是派生事实和公共制品引用，不是原始采集数据。Inference Lab 的清单，公开节点不能带：

  • home/workspace 路径
  • credentials / 环境值 / provider request ID
  • raw prompts / model responses
  • 无关进程身份 / target PID
  • 设备序列号 / 稳定设备标识
  • 账户 ID / 发票 / 信用 / 私有定价
  • 含其他 app/用户的 raw trace

实践：隐私不是结尾跑个 regex。是采集时就用闭文件 allowlist + SHA256SUMS。验证拒绝异常文件、目录、symlink、home 路径、UUID、credential 形 token、邮箱、raw trace 路径。原始 trace 用完即删，只发派生摘要。

十、一个端到端的 lineage

Inference Lab 展示了一条完整 lineage（五个阶段的解释投影，不是图里的新节点）：

model pin
  → collection（public_path + source commit）
  → verification（adapter 名+版本 → bundle verifier）
  → report（artifact set hash）
  → article claim（文章 cite report，但不成为证明自己的证据）

例如 qwen38-27b-m5-pro-clean-boot-autopsy-20260901：

  • model pin: mlx-community/Qwen3.8-27B-4bit@3e6447f...
  • collection: public path + source commit 2519bc8...
  • verification: oom_autopsy_v1 → oom-autopsy.verify_bundle v1
  • report: oom-autopsy-summary.json, artifact set sha256:1096de51...

文章 cite report，但文章不成为证明自己 claim 的证据。 这个边界防自指。

十一、hash / checksum / sealed / signed 的用词纪律

Inference Lab 反复强调用词精确：

词 何时能用
hash / checksum 有 SHA-256 摘要，能检测变更
sealed / tamper-evident hash 链让变更可检测
signed 只有真实密码学签名且已验证时
verified 跑了 verifier adapter 且通过

hash 不是 tamper-proofing，signed 要真签名。 别滥用"signed"——一个 checksum 不等于签名。这是工程诚实。

十二、怎么落地你的证据体系

不需要照搬 Inference Lab 的 schema，但要落实它的纪律。一个最小实践：

  1. 每个性能实验建一个 evidence dir，含 manifest + summary + samples + logs + SHA256SUMS。
  2. pin 到精确 commit：模型 revision、框架 commit、你的 benchmark 代码 commit。
  3. 每个数字旁边写 lineage 八维（至少 model/runtime/workload/evaluator/scope/失败状态）。
  4. claim 三态：每个证据写 supported/unsupported/N-A。把"这不证明什么"显式列。
  5. null 不当 zero。
  6. 独立 oracle 校验关键 claim（cache 命中、dispatch 数、break-even 是观测还是建模）。
  7. 可比性检查：横评前对齐契约或标不可比，排除项写出来。
  8. fail closed：制品 hash 不匹配 / commit 不对 → 拒发版。
  9. 隐私 allowlist：闭文件集 + SHA256SUMS，原始敏感数据不进 public 制品。
  10. 文章/报告 cite 制品，不自证。

十三、实践 checklist：证据体系

  • [ ] 每个性能结论有 evidence dir + 制品 + SHA256SUMS
  • [ ] pin 到精确 commit（模型/框架/你的代码）
  • [ ] 每个数字旁填 lineage 八维
  • [ ] claim 三态显式标，"这不证明什么"写出来
  • [ ] null 不当 zero
  • [ ] 关键 claim 用独立 oracle 校验
  • [ ] 横评对齐契约或标不可比，排除项写出来
  • [ ] 制品 hash 不匹配 / commit 不对 → fail closed 拒发版
  • [ ] 隐私闭文件集 allowlist，原始敏感数据不入 public 制品
  • [ ] 文章 cite 制品不自证；用 hash/checksum/signed 精确
